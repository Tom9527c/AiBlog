# AiBlog React 博客重构方案

状态：用户已于 2026-09-08 确认，进入实施。

## 目标与边界

在 AiBlog 下新增 React 博客端，重现 Tom9527c.github.io-main 的页面结构、样式、响应式行为和交互动画；全部业务数据由 AiBlog 的 NestJS 后端和现有本地 MySQL 管理。现有 Vue 后台继续使用，博客模块由外链改为可展开的“博客管理”。用户账户复用现有体系。

不迁移旧文章、评论、相册照片、追番条目及个人资料等业务数据。可复用原站布局样式、图标、装饰性静态资源和动画参数；业务图片与个人资料后续通过后台配置。初始数据库只写必要的模块配置、导航结构与后台权限菜单，内容为空时显示对应空态。测试样例仅用于开发验收，不成为正式业务数据。

不自动暂存、提交或推送 Git。

## 已核实的现状

- AiBlog 根目录不是 Git 仓库，nest-admin 和 vue3-naive-admin 分别为独立 Git 仓库，检查时二者工作区均无改动。
- 后端：NestJS 10、TypeORM、MySQL、Redis、JWT、现有用户及角色权限。
- 管理端：Vue 3、TypeScript、Naive UI、Vite，使用数据库动态路由。
- Docker 中 nest-mysql（MySQL 8，3306）和 nest-redis（Redis 7.4.1，6379）运行正常；已使用项目环境配置成功执行只读查询，未输出凭据。
- 当前数据库没有博客内容表。sys_menu 中 id=83 为“博客”父级，id=49 为指向 mrzym.top 的博客外链；静态路由、类型和国际化中也有旧博客项。
- 旧博客是 Hexo/AnZhiYu 静态生成结果，共有 193 个 HTML 文件，无 React 或 Hexo 源工程。重复文章、分页、分类、标签页面可抽象成同类 React 模板。
- 原站依赖本地 CSS/JS 和外部 CDN，包括 Swiper、Fancybox、播放器、搜索、主题、瀑布流等。已完成源码初查，浏览器中的动画基准和外部服务可用性尚待逐页验证。
- 当前 Public 装饰器会跳过身份认证，AllowAnon 则仍要求登录。博客需要能识别可选登录身份的读取路径，不能直接沿用 Public 后就认为用户已认证。

## 技术方案选择

1. **推荐：React + TypeScript + Vite 独立博客应用，共用 NestJS API。** 目录清晰，可最大程度沿用旧站 CSS 与动画参数，后台改动遵循已有模式，部署时通过统一站点入口分发博客、后台和 API。
2. React + Next.js：适合服务端渲染和更强的搜索引擎收录要求，但增加 Node 渲染服务、部署和认证衔接工作。当前先保留每页标题、描述和路由结构，若要求 SSR，可在实施前选择此方案。
3. 把静态 HTML 嵌入 React 容器：初始视觉还原快，但原全局脚本、PJAX 和 React 生命周期冲突，难以实现可靠的数据管理和访问控制，不采用。

建议目录：

```text
AiBlog/
  blog-web/                  React 博客应用
  nest-admin/                现有后端，新增 blog 模块
  vue3-naive-admin/           现有后台，新增博客管理页面
  docs/superpowers/specs/    方案及验收资料
```

React Router 管理页面跳转；布局、导航、侧边栏、页脚、搜索、主题设置、播放器为共享组件。旧站 DOM 中影响样式的层级和类名优先保留，交互改写成 React 组件和可清理的 hooks，避免残留全局监听器、定时器或重复初始化。

## 数据与接口

在现有数据库增量新增 blog_ 前缀表，覆盖站点配置、前台导航、文档、分类、标签及关系、相册与照片、追番、关于本人、说说、友链、朋友圈、收藏、音乐、评论。编辑人和评论作者关联现有 user，不新建账户体系。

核心业务使用明确字段和关系；站点装饰、关于本人卡片等组合配置允许使用经过结构校验的 JSON。文件上传复用现有存储模块。列表采用后台分页、筛选和排序。读接口按用途投影字段，不能直接返回完整实体。

- 公开读取：/blog/public/...，在现有全局 API 前缀下提供站点、菜单、内容列表、搜索、详情和访问状态。
- 内容解锁：/blog/public/.../unlock，验证密码后签发限时且限定到该资源的凭证。
- 后台管理：/blog/admin/...，按站点、菜单、文档等资源分控制器，并使用现有 RBAC 权限体系。
- 登录、验证码、注册、账号信息沿用现有认证服务和校验约束，前台使用适配后的博客风格界面。

文档列表卡片可公开显示管理员明确设置的标题、封面、摘要和访问标识。受限正文不得用于自动摘要、搜索匹配片段或相关推荐。受限相册不得提前返回原图地址；私有媒体需要鉴权下载或受限时效地址，不把永久公开地址作为访问控制。

数据库变更使用可重复执行的增量迁移/初始化脚本。升级已有博客父菜单，移除对应外链入口并新增细分菜单与权限关联；不删除原有用户、角色及其他系统菜单。执行前保存相关菜单和权限记录；不使用重置数据库或导入全量旧 SQL 的方式。

## 用户与内容访问控制

同一用户体系定义为共用 user、账号密码、账号状态、令牌验证、退出和角色权限。普通博客用户获得阅读、评论等能力，不自动获得后台管理权限。

默认每项内容支持三种互斥模式：

- 公开：未登录可以阅读。
- 登录可见：登录 AiBlog 账户后阅读。
- 密码可见：输入该内容访问密码即可阅读，不强制登录。

以上默认应用于文档、相册/照片、说说和可配置内容页；相册下的图片继承相册要求，单张图片可进一步收紧，不能绕过相册限制。菜单隐藏只影响展示，不代替内容接口鉴权。

密码通过 Argon2 哈希保存，接口不返回原始密码或哈希。解锁凭证限定内容 ID、内容类型、有效期和密码版本；换密码或变更访问规则后，旧凭证失效。错误密码限流。详情、搜索、随机文章、上下篇、相关推荐、评论及媒体入口统一执行访问规则，草稿不对公众返回。受限响应避免公共缓存。

部署默认采用同一站点入口：博客 /，后台 /admin/，API /api/（或沿用现有可配置前缀）。统一认证状态的实现必须同时覆盖退出和令牌失效；如最终部署为不同域名，需要单独配置可靠的跨站登录衔接，不能假设不同源 localStorage 可以共享。开发代理与生产反向代理均提供明确配置。

## 还原与交互验收

以旧站实际 HTML、CSS、JS 为依据建立页面和交互清单，先启动只读旧站预览，再以相同尺寸和代表性测试内容对照 React 实现。无旧数据的正式空态与视觉回归所需测试数据分开处理。

公共交互至少覆盖：顶部导航及下拉、滚动吸顶/隐藏、手机侧栏及遮罩、控制台、浅色/深色主题、显示设置持久化、搜索弹窗、加载与切页过渡、返回顶部与阅读进度、右键菜单、原有快捷键、提示消息、播放器展开/播放/暂停、背景与装饰动画。原站已启用的交互才纳入还原，不因为目录存在未使用脚本就额外开启特效。

页面交互至少覆盖：首页卡片/轮播/分类条及分页、文章目录跟随/锚点滚动/代码复制折叠/图片放大、归档分组、分类标签跳转、相册瀑布流/加载更多/灯箱、追番状态切换、关于页卡片动画、说说展开、友链分组、朋友圈切换、音乐列表播放和留言回复。

分辨率检查：360、390、768、1024、1440、1920 像素宽度；检查触屏操作、长标题、菜单溢出、图片尺寸变化、横竖屏布局。每个页面同时检查浅色/深色的代表状态。路由切换、主题切换和组件卸载后不得重复绑定事件或累积动画循环。

不能将“所有动画一致”仅以构建通过作为证据。对缺失的远程资源和无法工作的原外部服务记录清单，采用本地化依赖或相同交互的替代实现，并列出仍不能验证的差异。

## 实施顺序与完成标准

1. 建立旧站逐页、公共交互和动画基准清单，确认资源依赖与新目录运行约定。
2. 实现数据库实体、增量迁移、公共读取、后台 CRUD、访问控制与统一用户接入。
3. 实现后台“博客管理”全部细分页面，打通菜单、内容发布、文件上传及权限。
4. 实现 React 公共布局和所有页面模板，连接真实 API，逐项迁移交互与动画。
5. 执行本地迁移并完成 MySQL/Redis 联调；从后台录入测试内容，验证博客实时读取、编辑、发布、排序和隐藏。
6. 执行访问控制边界测试、后端与两端构建/类型检查，以及 PC/手机多尺寸浏览器验证，交付启动与部署说明和已验证/未验证清单。

重点自动化测试覆盖：匿名/已登录/失效令牌、正确/错误/过期/换密码后的解锁凭证、草稿不可读、搜索无正文泄漏、受限相册媒体不可绕过、普通用户不能调用后台写接口。管理流程验证覆盖每项资源的创建、修改、删除/隐藏、排序及前台结果。

最终完成标准是后台可管理、数据库可持久化、前台可展示、访问规则有效、主要交互逐项对照通过；仅页面壳、硬编码内容或前端遮罩不算完成。
