# 音乐馆维护

## 使用与恢复
后台「音乐管理 → 歌单音乐库」填 QQ 分享链接或 ID，生成同步预览，核对新增/移除/修改后确认更新。第一版仅手动同步，无后台周期请求。歌单更新与网站部署相互独立。

手动音乐保留在第二个标签，并始终与歌单音乐库合并展示。仅合并已发布、到达发布时间且当前访客可读取的内容；锁定内容不展示。清空歌单音乐库只移除该来源的曲目，不会隐藏独立维护的手动音乐。此规则按2026-09-23用户反馈更新，替代原先的“仅未配置时回退”规则。

两路数据分别加载。任一路失败时保留成功加载的曲目并显示重试入口，双方均失败且无曲目时显示加载错误。手动音乐使用独立身份标识，播放前仍通过详情接口检查访问权限。

音乐管理顶部的「页面设置」控制独立封面头部，与追番列表使用相同组件。开启后显示标题、副标题和头图，关闭保留原全屏听歌布局。播放器模糊背景始终跟随当前曲目封面，无封面时保留渐变。新增/编辑手动音乐只显示音乐所需字段，不显示正文、摘要和固定标识设置，旧数据保留。

同步失败不会覆盖已发布快照。查看最近尝试/成功拉取时间、连续失败次数及错误提示。页面刷新仍能恢复待确认预览；预览有效期24小时，新的同步/导入/编辑会替换旧预览。两人同时操作时旧 revision 无法提交。

每次确认更新保存上一版快照。需要恢复时先「导出上一版」，再「导入 JSON → 预览 → 确认更新」。当前/上一版导出均为紧凑 JSON，保证1MiB以内的有效快照可以回导。长期历史请自行保存导出文件。导出内容不含登录凭证。

QQ接口长期不可用时，可导入备份继续展示，或添加/编辑手动曲目（歌名、歌手、封面、音频HTTP(S)地址、LRC歌词）。歌单上限1000首，JSON上限1MiB。同步QQ会以平台信息生成新预览，手动修正不会自动永久覆盖平台信息，请核对“修改”列表并保留备份。

## QQ 接口失效时修改哪里
- `nest-admin/src/modules/blog/qq-music.provider.ts` 是唯一QQ传输适配器，提供 playlist(source) / media(track)。目前歌单调用 music.srfDissInfo.DissInfo.CgiGetDiss；音频调用平台 vkey 接口，歌词调用 QQ lyric 接口。
- `music-library.ts` 定义标准快照、URL校验、差异算法。替换QQ请求时保持标准输出即可；无需修改两端页面。
- `music-library.service.ts` 负责预览、并发、快照与播放短缓存；`music-library.store.ts` 使用数据库事务行锁。
- 只允许固定QQ主机发起服务器请求。不提供任意接口URL配置，不要求个人Cookie。
- 修改适配器后运行 `npm test -- --runInBand music-library`、`npm run build`，再用真实歌单生成预览，确认数量/唯一性/分页完整性。至少验证网络超时、错误结构和截断列表不会覆盖快照。

## 部署
先在 nest-admin 目录执行 `node scripts/music-library-migrate.cjs`，只新增 `blog_music_library` 表，重复运行安全。完整 `scripts/blog-migrate.cjs` 也包含同样建表语句。之后部署后端及两个前端。无需重置原表，数据库备份应包含新增表。

## 播放范围
歌单可公开读取不代表歌曲可完整播放。仅使用QQ匿名请求实际返回的音源。没有地址/浏览器播放失败时停止并显示QQ入口，不伪装正在播放。音频地址仅短期缓存，不作为持久快照写入。手动有效音源可使用同一播放器。歌词加载失败不应阻断可用音源。

本次实测 9766739035「新建歌单8」完整36首、首曲歌词正常，首曲未返回可播放音源。未承诺其他歌曲均可在线播放。

## QQ 登录需求已取消
2026-09-23 用户在真实联调未通过后取消登录需求。登录入口、接口、凭证处理及 MQTT 依赖已移除，继续使用匿名音源、手动音乐和官方歌曲链接。没有完成真实账号登录或会员播放验证。

## 自动跳过和浮动播放器
音乐馆与首页浮球复用歌单加载及播放器逻辑，包含QQ快照和可读取的手动音乐。无音源、请求异常、媒体加载失败会提示并在350毫秒后跳到下一首；加载超过20秒同样处理。同一次连续失败中每首只尝试一次，全部不可用则停止，手动选曲或重试会开启新一轮。浏览器要求点击授权播放时停在当前曲目，不自动跳过；取消加载或离开播放器时清除待跳转任务。

浮球封面按钮用于播放/暂停，歌名或歌词用于展开控制面板。播放时胶囊显示同步LRC当前行，面板支持进度拖动、键盘调节、音量、循环模式和选曲，可隐藏浮球歌词。浮球与音乐馆在对应路由互斥挂载，不会同时播放两个音频；进入/离开音乐馆仍遵循原先停止当前播放器的行为。
